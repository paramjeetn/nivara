## 1. Executive Summary & Objective

### 1.1 Objective
The core tenet of Step 4 is **"Turn 'it works' into reproducible evidence."**  
Prior to this step, Nivara's anomaly detection pipeline and time-series forecasters generated alerts and forward projections, but lacked an automated, objective, and reproducible evaluation harness. There was no quantitative benchmark demonstrating whether the multi-layered detection engine outperformed naive statistical detectors (e.g. static thresholds or rolling z-scores), or whether parametric forecasting models (Ridge regression and Meta Prophet) outperformed simple seasonal persistence.

Step 4 bridges this gap by creating a rigorous verification harness:
1. **Baselines Engine (`src/campus_energy/eval/baselines.py`):**
   - Implemented `StaticThresholdDetector` (flags readings exceeding static kW ceiling or historical percentiles).
   - Implemented `RollingZScoreDetector` (flags sustained readings where 24h trailing z-score $\ge 3.0$).
   - Implemented `SeasonalNaiveForecaster` ("same slot last week", $t - 7\text{d}$, with daily and intraday fallback).
2. **Anomaly Evaluation Suite (`src/campus_energy/eval/anomaly_eval.py`):**
   - Built a strict event-level evaluation framework matching detections against ground-truth injected faults (`anomaly_ground_truth.csv` and `events.csv`).
   - Implemented systematic ablation testing comparing the **Full Layered Engine**, each of the **5 individual layers** (Statistical Ridge, Unoccupied Rule, Hydraulic Dry-Run Rule, Sensor Dropout Rule, Isolation Forest ML), and both **naive baselines**.
   - Computed Precision, Recall, F1 Score, and Detection Delay (minutes from event inception to first alert) per fault type and overall.
3. **Forecast Evaluation Suite (`src/campus_energy/eval/forecast_eval.py`):**
   - Enforced a strict temporal holdout protocol: first 21 days for training, final 7 days for test, guaranteeing zero future context leakage.
   - Evaluated Ridge regression, Meta Prophet, and Seasonal-Naive across day types (`overall`, `weekday`, `weekend`, `holiday`).
   - Computed Mean Absolute Percentage Error (MAPE), Mean Absolute Error (MAE), and Root Mean Squared Error (RMSE).
4. **Reproducible Pipeline & Deliverables (`src/campus_energy/eval/run_all.py`):**
   - Locked random seed (`np.random.seed(42)`).
   - Exported clean machine-readable `reports/eval/summary.json`.
   - Rendered publication-ready comparative plots `reports/eval/anomaly_f1_comparison.png` and `reports/eval/forecast_mape_comparison.png`.
   - Generated formal markdown report `reports/eval/README.md`.
5. **Project Ergonomics & UI Integration:**
   - Authored root `Makefile` exposing standard targets: `eval`, `test`, `run`.
   - Embedded interactive **🔬 Verification & Evidence** section in Streamlit Dashboard Page 1B (Governance & Policy) with the mandatory disclaimer:
     `"Evaluated on synthetic data with injected faults; validates the pipeline, not real-world accuracy."`
6. **Comprehensive Test Suite (`tests/test_eval_harness.py`):**
   - Added 5 unit tests verifying hand-built edge-case event matching (asserting exact TP, FP, FN, precision, recall, and delay), detector baselines, and seasonal-naive fallbacks.

## 3. Evaluation Methodology & Metric Formulations

### 3.1 Anomaly Detection Event-Level Matching
Energy faults in physical buildings are temporal events with non-zero durations rather than isolated instantaneous points. To prevent artificial score inflation while rigorously penalizing false alarms, Nivara implements an **event-level overlap matching rule**:

1. **Spatial & Temporal Alignment:**  
   An alert $A = (\text{asset}_A, t_{\text{start}}^A, t_{\text{det}}^A)$ matches a ground-truth event $E = (\text{asset}_E, t_{\text{start}}^E, t_{\text{end}}^E)$ if and only if:
   $$\text{asset}_A = \text{asset}_E \quad \land \quad \neg \left( t_{\text{det}}^A < t_{\text{start}}^E - \tau \quad \lor \quad t_{\text{start}}^A > t_{\text{end}}^E + \tau \right)$$
   where $\tau = 60\text{ minutes}$ is the defined tolerance window.

2. **Event-Level Deduplication:**  
   If multiple alerts match the same ground truth event $E_j$, they count as **one** True Positive ($TP$) event match:
   $$TP = |\{ E_j \in \mathcal{E} : \exists A_i \text{ matching } E_j \}|$$

3. **False Negatives ($FN$):**  
   Any ground truth event with zero matching alerts is an $FN$:
   $$FN = |\mathcal{E}| - TP$$

4. **False Positives ($FP$):**  
   Any alert $A_k$ that does not overlap with any ground-truth event on its associated asset is counted as an $FP$:
   $$FP = |\{ A_k \in \mathcal{A} : \forall E_j \in \mathcal{E}, A_k \text{ does not match } E_j \}|$$

5. **Detection Delay:**  
   For each detected ground truth event $E_j$, detection delay measures the operational lag in minutes from fault start to first notification:
   $$\text{Delay}(E_j) = \max\left(0.0, \, \frac{t_{\text{det}}^{\text{first}} - t_{\text{start}}^{E_j}}{60\text{ seconds}}\right)$$

### 3.2 Load Forecasting Temporal Holdout
To prevent temporal leakage, evaluation strictly isolates past context from future testing:
- **Total Dataset:** 28 days (September 1, 2025 00:00 to September 28, 2025 23:55).
- **Split Timestamp:** September 22, 2025 00:00:00 ($T_{\text{split}} = T_{\text{start}} + 21\text{ days}$).
- **Training Set:** 6,048 observations ($t < T_{\text{split}}$).
- **Held-Out Test Set:** 2,016 observations ($t \ge T_{\text{split}}$).
- **Metrics Evaluated:**
  $$\text{MAE} = \frac{1}{N} \sum_{i=1}^N |y_i - \hat{y}_i| \quad (\text{kW})$$
  $$\text{MAPE} = \frac{100\%}{|\{i : y_i > 0.01\}|} \sum_{y_i > 0.01} \frac{|y_i - \hat{y}_i|}{y_i} \quad (\%)$$
  $$\text{RMSE} = \sqrt{\frac{1}{N} \sum_{i=1}^N (y_i - \hat{y}_i)^2} \quad (\text{kW})$$

## 5. Honest Scientific Findings & Discussion

### 5.1 Why Naive Anomaly Baselines Fail on Building Energy Telemetry
1. **The Static Threshold Blind Spot:**
   - Static threshold detectors (e.g. 95th percentile or $1.05 \times \text{rated capacity}$) fail completely on equipment left running after hours.
   - For example, classroom lighting drawing 1.71 kW overnight operates safely within its 1.80 kW rated nameplate capacity. An upper-bound threshold never triggers.
   - Similarly, when a water pump runs dry (zero flow), its power consumption remains below its maximum rated load; static thresholding cannot infer hydraulic disconnection.
   - Result: 1,034 false alarms triggered by normal daytime load peaks, yet zero contextual faults caught.
2. **The Rolling Z-Score Anomaly Masking Trap:**
   - Trailing statistical filters ($z = (y - \mu)/\sigma$) assume anomalies are transient, high-amplitude spikes.
   - When a fault persists for several hours (e.g. HVAC running from 19:00 to 03:00), the trailing rolling window incorporates the anomalous readings, rapidly inflating the trailing mean $\mu$ and standard deviation $\sigma$.
   - By the third hour, the relative z-score collapses back below 2.5, masking the ongoing waste.
3. **The Power of Physics-Informed Rules:**
   - The unoccupied operation rule, hydraulic dry-run rule, and sensor dropout rule each achieved **100% precision (0 false alarms)** on the specific faults they monitor.
   - Domain knowledge (checking occupancy sensors against lighting state, checking flow rate against pump power) provides decisive signal where purely statistical methods generate noise.

### 5.2 Why Seasonal-Naive Outperforms Parametric Models on Campus Load
- In academic campuses and institutional facilities, energy consumption is governed by rigid timetables (class hours, lab schedules, weekend closures).
- **Seasonal-Naive ($t - 7\text{d}$)** preserves exact recurring diurnal profiles, capturing abrupt 08:00 step increases and weekend baseline drops with extraordinary precision (**4.56% MAPE on weekends**).
- **Ridge Regression and Meta Prophet**, while effective at trend smoothing, struggle with sharp step changes between operational modes, overestimating weekend baselines (**72.33% weekend MAPE for Ridge**).
- **Architectural Lesson:** In institutional energy management, parametric forecasters should not replace seasonal calendar baselines; they should act as delta models trained on deviations from the seasonal-naive baseline.

## 7. Limitations & Next Steps (Transition to Step 5)

While Step 4 establishes rigorous empirical benchmarks, several technical limitations highlight the roadmap for **Step 5: Uncertainty Quantification & Prediction Intervals**:

1. **Point Forecasts vs Operational Risk:**  
   Currently, Ridge and Seasonal-Naive output single deterministic numbers. Facility operators making peak demand shaving or battery dispatch decisions require calibrated **uncertainty bands (e.g. 80% and 95% prediction intervals)** to manage grid penalty risks.
2. **False Positive Burden in Unsupervised ML:**  
   Isolation Forest generated 445 outlier clusters on normal daily variations. Step 5 will investigate combining conformal prediction and dynamic adaptive thresholds to suppress false alarms.
3. **Real-Time Streaming Evaluation:**  
   The current harness operates in batch-mode across the 28-day historical record. Step 5 and beyond can extend this into an online evaluation harness measuring streaming drift and latency in real time.
